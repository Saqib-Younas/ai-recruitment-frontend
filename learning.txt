# Database Index

## Definition of Database Index

Database Index ek special data structure hota hai jo database me data ko **jaldi search aur retrieve (find)** karne ke liye use hota hai.

Ye bilkul book ke index ki tarah hota hai. Book ke index me topic ke sath page number diya hota hai jisse hum directly required page par pohanch jate hain. Isi tarah database index data ka location store karta hai jisse database ko har row check nahi karni parti.

---

# Example of Database Index

Maan lo ek Student table hai:

| Roll_No | Name  | Class | City      |
| ------- | ----- | ----- | --------- |
| 101     | Ali   | 10    | Lahore    |
| 102     | Ahmed | 9     | Karachi   |
| 103     | Sara  | 10    | Islamabad |
| 104     | Usman | 8     | Lahore    |

Agar hum search karein:

```sql
SELECT * FROM Students WHERE Roll_No = 103;
```

## Without Index

Database har row check karega:

```
101 Ali ❌
102 Ahmed ❌
103 Sara ✅
```

Agar table me lakho records hon to search slow ho jayegi.

## With Index

Database ek index banata hai:

| Roll_No | Location |
| ------- | -------- |
| 101     | Row 1    |
| 102     | Row 2    |
| 103     | Row 3    |
| 104     | Row 4    |

Ab database directly:

```
103 → Row 3 → Sara
```

find kar leta hai.

---

# Types of Database Index

## 1. Primary Index

### Definition:

Primary Index wo index hota hai jo table ki **Primary Key** par banaya jata hai.

### Example:

Student table:

| Student_ID | Name  |
| ---------- | ----- |
| 101        | Ali   |
| 102        | Ahmed |
| 103        | Sara  |

Student_ID unique hoti hai, isliye is par primary index ban sakta hai.

---

## 2. Secondary Index

### Definition:

Secondary Index primary key ke ilawa kisi aur column par banaya jata hai.

### Example:

Agar hum Name par index banaye:

| Name  | Location |
| ----- | -------- |
| Ali   | Row 1    |
| Ahmed | Row 2    |
| Sara  | Row 3    |

Ab Name se searching fast ho jayegi.

---

## 3. Clustered Index

### Definition:

Clustered Index table ke actual data ko index ke order ke mutabiq arrange karta hai.

### Example:

Before:

```
103 Sara
101 Ali
102 Ahmed
```

After Clustered Index:

```
101 Ali
102 Ahmed
103 Sara
```

Ek table me sirf ek clustered index hota hai.

---

## 4. Non-Clustered Index

### Definition:

Non-Clustered Index data se alag store hota hai aur actual data ka address rakhta hai.

### Example:

Table:

```
101 Ali
102 Ahmed
103 Sara
```

City par non-clustered index:

```
Islamabad → Sara ka address
Karachi → Ahmed ka address
Lahore → Ali ka address
```

---

## 5. Unique Index

### Definition:

Unique Index column me duplicate values ko allow nahi karta.

### Example:

Email column:

```
ali@gmail.com
sara@gmail.com
```

Agar koi same email dobara insert kare:

```
ali@gmail.com
```

Database error show karega.

---

## 6. Composite Index

### Definition:

Composite Index do ya do se zyada columns par banaya jata hai.

### Example:

Index:

```
Class + City
```

Query:

```
Find students of Class 10 from Lahore
```

Ye search fast karega.

---

## 7. Full Text Index

### Definition:

Full Text Index large text data me words search karne ke liye use hota hai.

### Example:

* Books
* Articles
* Documents

Agar kisi article me "Database" word search karna ho to full text index help karta hai.

---

# Advantages of Database Index

## 1. Fast Searching

Index ki wajah se data jaldi find hota hai.

Example:

Without Index:

```
100000 records check karne par sakte hain
```

With Index:

```
Direct required record mil jata hai
```

---

## 2. Faster Sorting

ORDER BY queries jaldi execute hoti hain.

Example:

```
Students ko Name ke order me show karna
```

---

## 3. Faster Joins

Indexes tables ko combine karne me help karte hain.

Example:

Students table aur Marks table ko ID ke through join karna.

---

## 4. Data Uniqueness

Unique Index duplicate data ko rokta hai.

Example:

Same email dobara save nahi ho sakti.

---

# Disadvantages of Database Index

## 1. Extra Storage Required

Index ko store karne ke liye extra disk space chahiye hoti hai.

Example:
```
Table size = 100 MB
Index size = 20 MB

Total = 120 MB
```

---

## 2. Insert Operation Slow

Jab naya record add hota hai to database ko table ke sath index bhi update karna parta hai.

Example:

New student add karna:

```
105 Hassan
```

Database:

1. Student add karega
2. Index update karega

---

## 3. Update Operation Slow

Agar indexed column change hota hai to index bhi update hota hai.

Example:

```
Ali ka Name change karke Ahmed karna
```

---

## 4. Delete Operation Slow

Record delete karne par index se bhi entry remove hoti hai.

Example:

```
Student Sara delete karna
```

---

## 5. Too Many Indexes

Agar bohat zyada indexes bana diye jayein to database performance kam ho sakti hai.

---

# Index vs No Index

| Without Index          | With Index               |
| ---------------------- | ------------------------ |
| Har row check hoti hai | Direct data milta hai    |
| Search slow hoti hai   | Search fast hoti hai     |
| Storage kam lagti hai  | Storage zyada lagti hai  |
| Insert fast hota hai   | Insert slow ho sakta hai |

---

# Conclusion

Database Index database ki ek shortcut list hoti hai jo data ko jaldi find karne me help karti hai.

**Index ka main benefit:**

* Data searching fast hoti hai.

**Index ka main drawback:**

* Extra storage leta hai aur Insert, Update, Delete operations slow kar sakta hai.




Database Index ek special data structure hai jo database mein data ko fast search aur retrieve karne ke liye use hota hai.

Zyada tar relational databases (jaise MySQL aur PostgreSQL) B+ Tree index use karti hain.

Jab hum indexed column par query chalate hain, to database B+ Tree traverse karta hai aur directly required record (ya uske pointer) tak pohanch jata hai. Is wajah se har row scan karne ki zarurat nahi parti.

Example:

SELECT * FROM Users
WHERE email = 'ali@gmail.com';

Agar email par index hai:

❌ Database poori table scan nahi karega.
✅ B+ Tree ko traverse karke matching record tak jaldi pohanch jayega.
Ek important correction

Aap ne kaha:

har node ak index hota

Ye bilkul accurate nahi hai.

Sahi baat:

Har node mein sorted keys (index values) aur child pointers hote hain.
Leaf nodes mein actual row pointers (ya clustered index mein actual data) hota hai.


B+ Tree mein parent node mein "2 values hoti hain" ya B-Tree mein "1 value hoti hai" aisa koi fixed rule nahi hai.

Sahi Difference
B-Tree	B+ Tree
Data internal nodes aur leaf nodes dono mein ho sakta hai.	Actual data sirf leaf nodes mein hota hai. Internal nodes sirf keys aur pointers rakhte hain.
Search kabhi internal node par hi khatam ho sakti hai.	Search hamesha leaf node tak jati hai.
Leaf nodes usually linked nahi hote.	Leaf nodes linked list ki tarah connected hote hain.
Range queries relatively slower hoti hain.	Range queries bohat fast hoti hain.
B+ Tree databases mein zyada kyun use hoti hai?

Range Search Fast

SELECT * FROM Employees
WHERE salary BETWEEN 50000 AND 100000;

Leaf nodes linked hone ki wajah se database sequentially records read kar leta hai.

Zyada Fan-out
Internal nodes mein sirf keys aur pointers hote hain (actual data nahi), isliye ek node mein zyada keys aa sakti hain. Is se tree ki height kam hoti hai aur search faster hoti hai.
Disk I/O Kam
Tree ki height kam hone ki wajah se disk accesses kam lagte hain.
Interview mein short answer

B-Tree mein data internal aur leaf nodes dono mein ho sakta hai, jabke B+ Tree mein actual data sirf leaf nodes mein hota hai. Internal nodes sirf navigation ke liye use hote hain. Is wajah se B+ Tree ki fan-out zyada hoti hai, tree chhota rehta hai aur range queries aur searching dono fast hoti hain. Isi liye databases jaise MySQL aur PostgreSQL default indexing ke liye B+ Tree use karte hain.



Maan lo table hai:
ID	Name	Salary
3	Sara	70000
1	Ali	50000
5	Ahmed	90000
2	Bilal	60000
B-Tree

B-Tree mein actual data internal nodes aur leaf nodes dono mein ho sakta hai.

Example (simplified):

          [3, Sara]
         /         \
 [1, Ali][2, Bilal]   [5, Ahmed]

Yahan root node mein bhi actual record hai (3, Sara).

Agar search ID = 3 ho to root par hi mil gaya.

B+ Tree

B+ Tree mein internal nodes sirf keys rakhte hain. Actual data sirf leaf nodes mein hota hai.

            [3]
          /     \
       [1,2]    [5]
        |         |
------------------------------------
|1 Ali| -> |2 Bilal| -> |3 Sara| -> |5 Ahmed|
------------------------------------

Dhyan dein:

Upar wale nodes sirf keys hain.
Neeche leaf nodes mein actual records hain.
Leaf nodes ek dusre se linked hain.




✅ Clustered Index

Clustered Index table ke actual data ko index ke order mein physically arrange karta hai.

Example:

Table:

ID	Name
3	Sara
1	Ali
2	Bilal

Agar ID par clustered index bana dein:

Table physically ban jayegi:

ID	Name
1	Ali
2	Bilal
3	Sara

Yani table ka actual data hi sorted hota hai.

👉 Isliye ek table mein sirf 1 Clustered Index ho sakta hai, kyun ke data physically sirf ek hi order mein arrange ho sakta hai.

✅ Non-Clustered Index

Non-clustered index actual data ko move nahi karta.

Ye alag se ek structure banata hai jisme:

Name      Pointer
Ali   ---> Row 2
Bilal ---> Row 3
Sara  ---> Row 1

Jab query aati hai:

SELECT *
FROM Users
WHERE Name='Bilal';

Database:

Non-clustered index mein "Bilal" dhoondhta hai.
Pointer milta hai.
Pointer se actual table ki row read karta hai.
Difference
Clustered Index	Non-Clustered Index
Actual data physically sort hota hai	Actual data move nahi hota
Leaf node mein actual data hota hai	Leaf node mein pointer hota hai
Sirf 1 ho sakta hai	Multiple ho sakte hain
🎯 Interview Trick

Interviewer poochta hai:

"Clustered index sirf ek hi kyun hota hai?"

Best answer:

"Kyun ke table ka actual data physically sirf ek hi order mein arrange ho sakta hai."

## 1. Query Optimization kya hoti hai?

**Answer:**

Query optimization ek process hai jisme database queries ko improve kiya jata hai taa ke woh kam time, kam memory taur kam CPU resources use karte hue execute hon.

Database optimizer multiple execution plans mein se best plan select karta hai.

Example:

Slow query:

```sql
SELECT *
FROM Users
WHERE email = 'ali@gmail.com';
```

Agar email par index nahi hai to database puri table scan karega.

Optimization:

```sql
CREATE INDEX idx_email
ON Users(email);
```

Ab database directly matching record find kar sakta hai.

# 13. Normalization vs Denormalization

## Normalization

Data duplication kam karta hai.

Benefits:

* Data consistency
* Less storage

## Denormalization

Performance ke liye duplicate data store karta hai.

Benefits:

* Faster reads
* Less JOINs

Denormalization mein intentionally duplicate data store kiya jata hai taa ke read performance improve ho aur JOINs kam karne paren.







1. First Normal Form (1NF)

Rule: Har column mein single/atomic value honi chahiye. Multiple values ek cell mein nahi.

❌ Not 1NF:

Student_ID	Name	Subjects
1	Ali	DB, OOP, OS

Subjects mein 3 values hain.

✅ 1NF:

Student_ID	Name	Subject
1	Ali	DB
1	Ali	OOP
1	Ali	OS
2. Second Normal Form (2NF)

Rules:

Table 1NF mein ho.
Partial dependency nahi honi chahiye.

Example:

Student_ID	Course_ID	Student_Name	Course_Name
1	C01	Ali	DB
1	C02	Ali	OOP

Primary key = (Student_ID, Course_ID)

Yahan Student_Name sirf Student_ID par depend karta hai, poori key par nahi. Ye partial dependency hai.

Isliye tables separate karte hain:

Student

Student_ID	Student_Name
1	Ali

Course

Course_ID	Course_Name
C01	DB
C02	OOP

Enrollment

Student_ID	Course_ID
1	C01
1	C02
3. Third Normal Form (3NF)

Rules:

Table 2NF mein ho.
Transitive dependency nahi honi chahiye.

Example:

Student_ID	Student_Name	Dept_ID	Dept_Name
1	Ali	D01	Computer Science

Dependencies:

Student_ID → Dept_ID
Dept_ID → Dept_Name

Matlab Dept_Name indirectly Student_ID par depend kar raha hai. Ye transitive dependency hai.

Isko split karenge:

Student

Student_ID	Student_Name	Dept_ID
1	Ali	D01

Department

Dept_ID	Dept_Name
D01	Computer Science
4. BCNF (Boyce-Codd Normal Form)

BCNF, 3NF ka stronger version hai.

Simple rule: Har determinant candidate key hona chahiye.

Exam mein yaad rakhne ke liye:

1NF → Atomic values
2NF → No partial dependency
3NF → No transitive dependency
BCNF → Every determinant must be a candidate key


🔥 BCNF ko bas is tarah yaad karo:

Jo banda/value doosri value decide kar raha hai, kya woh khud unique hai?

Haan → BCNF ✅
Nahi → BCNF ❌
Ek aur super-simple example:

CNIC → Person Name

CNIC se person ka naam pata chal jata hai.

CNIC unique hota hai.

➡️ CNIC = Candidate Key ✅
➡️ BCNF okay ✅

🔹 Basic Terms

1. Attribute
Table ka column.
Example: Student_ID, Name, Age

2. Tuple
Table ki ek complete row/record.
Example: (1, Ali, 20)

3. Relation
Database mein table ko relation kehte hain.

4. Primary Key
Aisa column (ya columns ka group) jo har row ko uniquely identify kare.
Example: Student_ID

5. Candidate Key
Wo saare possible columns/groups jo uniquely row ko identify kar sakte hain. In mein se ek ko Primary Key banate hain.

6. Composite Key
Jab 2 ya zyada columns mil kar Primary Key banate hain.
Example: (Student_ID + Course_ID)

🔹 Dependencies

7. Functional Dependency (FD)
Jab ek attribute ki value se doosre attribute ki value determine ho jaye.

Example:

Student_ID → Student_Name

Matlab agar Student_ID pata hai, to Student_Name pata chal jayega.

8. Partial Dependency
Jab koi attribute composite key ke sirf ek part par depend kare, poori key par nahi.

Example:

(Student_ID, Course_ID) → Student_Name

Lekin actually:

Student_ID → Student_Name

To ye Partial Dependency hai.

9. Full Functional Dependency
Jab attribute poori composite key par depend kare, sirf ek part par nahi.

Example:

(Student_ID, Course_ID) → Grade

Grade student + course dono par depend kar raha hai.

10. Transitive Dependency
Jab dependency indirectly ho:

A → B
B → C

To:

A → C

Example:

Student_ID → Dept_ID
Dept_ID → Dept_Name

Isliye Student_ID → Dept_Name indirectly hai. Ye Transitive Dependency hai.


Transitive Dependency tab hoti hai jab dependency chain mein ho:

Student_ID → Teacher_ID → Teacher_Name

Yani:

Student_ID se Teacher_ID milti hai.
Phir Teacher_ID se Teacher_Name milta hai.
Isliye Student_ID se Teacher_Name indirectly mil raha hai.
Ek ID se doosri value mile, aur us doosri value se teesri value mile = Transitive Dependency ✅

🔹 Normalization Terms

11. Atomic Value
Cell mein sirf ek value ho.

❌ Subjects = DB, OOP, OS
✅ Subject = DB

12. Redundancy
Same data ka baar baar repeat hona.

Example: Har student ke record mein "Computer Science" baar baar likhna.

13. Anomaly
Poor database design ki wajah se hone wali problem.

Insertion Anomaly: Data insert karna mushkil ho.
Update Anomaly: Ek hi information multiple jagah update karni pade.
Deletion Anomaly: Ek record delete karne se accidentally important information bhi delete ho jaye.

14. Determinant
Functional dependency mein left side wala attribute.

Student_ID → Student_Name

Yahan Student_ID = Determinant.

15. Candidate Key
Minimal key jo row ko uniquely identify kare.

16. Super Key
Aisa attribute/group jo row ko uniquely identify kare, lekin zaroori nahi ke minimal ho.

Example:
Student_ID → Super Key
Student_ID + Name → bhi Super Key, lekin extra attribute hai.



🔑 Super Key kya hoti hai?

Super Key = ek ya zyada columns ka aisa combination jo table ki har row ko uniquely identify kare.

Example:

Student_ID	Name	Email
1	Ali	ali@gmail.com
2	Sara	sara@gmail.com

Agar Student_ID unique hai:

Student_ID → Super Key ✅

Agar Email bhi unique hai:

Email → Super Key ✅

Ab:

Student_ID + Name → Super Key ✅

Kyunki Student_ID already unique hai, isliye Name add karne ke baad bhi row unique rahegi.


Maan lo ID unique hai.

Pehle Super Key

ID se Ali ki row mil gayi.

➡️ ID = Super Key ✅

Ab ID + Name se bhi Ali ki row mil jayegi.

➡️ ID + Name = Super Key ✅

Lekin Name ki zaroorat nahi thi, kyunki ID akela hi kaam kar raha tha.

Ab Candidate Key

Candidate Key ka matlab:

"Jo minimum cheez row ko identify kar de."

ID akela row identify kar raha hai.

➡️ ID = Candidate Key ✅

ID + Name mein Name extra hai.

➡️ ID + Name = Candidate Key nahi ❌

Important Interview Point:

Server B = weak

Stored Procedure kya hai?
Stored Procedure SQL (Structured Query Language) code ka ek pre-compiled block hota hai, jise database server ke andar save (store) karke rakh liya jata hai.

Jab aapko wahi code dobara chalana ho, toh aapko poori query baar-baar likhne ki zaroorat nahi padti; aap sirf us procedure ka naam call (execute) karte hain, aur wo execute ho jata hai.

Real-World Example
Sochiye aapke paas ek e-commerce website hai. Har roz hazaron log "Place Order" ka button dabate hain. Is process mein 5 alag-alag queries run hoti hain (jaise stock check karna, order table mein entry karna, user ka balance kaatna, etc.).

Bina Stored Procedure ke: Aapko har baar application se wo saari 5 queries database ko bhejni padengi.

Stored Procedure ke sath: Aap wo saari queries database ke andar ek procedure mein save kar denge jiska naam PlaceOrder hoga. Ab application se sirf ek command jayegi: EXEC PlaceOrder.

Stored Procedure ke Fayde (Advantages)
1. Performance (Tezi): Stored Procedures compiled hote hain. Database server inka execution plan pehle hi bana kar rakh leta hai, jiski wajah se ye regular queries ke mukabla zyada tezi se run hote hain.

2. Reusability (Dobara Istemaal): Ek baar code likh kar database mein save kar lo, aur multiple applications ya alag-alag places se use bar-bar call kar sakte ho.

3. Security: Aap direct tables par users ko access dene ke bajaye sirf Stored Procedure ko execute karne ki permission de sakte hain, jisse SQL Injection jaise attacks ka khatra kam ho jata hai.

4. Network Traffic Kam Hota hai: Agar aapko 10 complex queries chalani hain, toh bina procedure ke aapko 10 alag queries network par bhejni padengi. Procedure ki surat mein sirf ek chhota sa naam network par bhejta hai.

Example (SQL Server / MySQL Syntax)
1. Stored Procedure Kaise Banayein (Create):
Maante hain hamare paas ek table hai jiska naam Employees hai aur humein ek aisa procedure banana hai jo kisi specific department ke employees ki list de.

SQL
CREATE PROCEDURE GetEmployeesByDept 
    @DeptName VARCHAR(50)
AS
BEGIN
    SELECT * FROM Employees WHERE Department = @DeptName;
END;
2. Stored Procedure Kaise Chalayein (Execute):
Jab aapko is procedure ko run karna ho, toh aap ye command likhenge:

SQL
EXEC GetEmployeesByDept @DeptName = 'IT';


Cache mein kya save hota hai? (Execution Plan)
Stored Procedure jab aap pehli baar chalate hain, toh database engine yeh tay karta hai ki is code ko chalane ka sabse tez aur asaan tarika (execution plan) kaun sa hoga. Database is plan ko memory (cache) mein save kar leta hai.

Fayda: Agli baar jab aap wahi procedure chalate hain, toh database ko naya plan banane ki zaroorat nahi padti, wo pehle se save kiye hue plan ka istemal karta hai. Isliye yeh bina procedure wali query se thoda tez chalta hai.

Lekin result cache nahi hota: Iska matlab ye nahi hai ki purana data hi wapas mil jayega. Agar database table mein koi naya record jud gaya hai, toh wo naye record ke sath result dikhayega.

CTE kya hota hai? (Asaan Bhasha mein)
CTE ka matlab hota hai Common Table Expression.

Isse aap ek temporary table (kuch samay ke liye banne wali table) bana lete hain, jo sirf ussi waqt tak zinda rehti hai jab tak aapki main query chal rahi hoti hai. Query khatam hote hi wo temporary table apne aap khatam (delete) ho jati hai.

Real-Life Example se Samjho
Sochiye aapko ek bada sa hisaab-kitaab karna hai:

Pehle aapko sabhi employees ki Average Salary nikalni hai.

Phir check karna hai ki kiski salary us average salary se zyada hai.

Bina CTE ke (Lamba aur Mushkil tarika): Aapko ek query ke andar hi doosri query (Subquery) likhni padegi, jisse code padhne mein bohot ganda aur samajhne mein mushkil ho jata hai.

CTE ke sath (Smart tarika): Aap pehle ek choti si temporary table bana lete hain jisme Average Salary store ho jati hai, aur phir apni main query mein seedha uska istemal kar lete hain. Code bilkul saaf lagta hai!

CTE Kaise Likhte hain? (Syntax)
CTE banane ke liye hum WITH keyword ka istemal karte hain.

SQL
WITH MyTemporaryTable AS (
    -- Yahan aapki choti si query aayegi jo temporary table banayegi
    SELECT AVG(Salary) AS AvgSal FROM Employees
)
-- Yahan aapki Main Query aayegi jo us temporary table ko use karegi
SELECT * FROM Employees 
WHERE Salary > (SELECT AvgSal FROM MyTemporaryTable);
CTE kyun use karte hain? (Faide)
Code Saaf lagta hai (Readability): Badi aur gandi queries ko chote-chote tukdo (steps) mein baant deta hai, jisse koi bhi aasaani se samajh sakta hai.

Subquery se Behtar: Jo kaam aap subqueries (query ke andar query) se karte hain, wahi kaam CTE se bohot hi saaf tarike se ho jata hai.

Recursive Queries: Agar aapko tree structure wala data nikalna ho (jaise Boss ke niche Manager, Manager ke niche Employee), toh uske liye CTE ka koi mukabla nahi hai.

Stored Procedure aur CTE mein kya Fark hai?
Stored Procedure: Ek permanent function ki tarah hai jo database mein save ho jata hai aur aap ise mahino baad bhi chala sakte hain.

CTE: Sirf ek ek baar chalne wali temporary table hai. Jaise hi aapki query run ho kar khatam hui, CTE ka wajood khatam ho jata hai. Ye database mein save nahi rehta.










1. View (Normal View)
Kya hota hai: Yeh koi alag se table nahi hoti. Yeh sirf ek saved query hoti hai.

Kaise kaam karta hai: Jab bhi aap View ko dekhne ke liye query chalate hain (SELECT * FROM MyView), database background mein turant wahi purani original tables se data nikal kar lata hai. Isme data pehle se save nahi hota, har baar naya (fresh) data calculate hota hai.

Fayda: Code chhota ho jata hai aur security ke liye acha hai (aap users ko poori table dene ke bajaye sirf view de sakte hain).

Nuqsan: Agar query bohot badi aur complex hai, toh View ko chalane mein bhi utna hi time lagega jitna normal query ko lagta hai.

2. Materialized View
Kya hota hai: Yeh sirf ek saved query nahi hai, balki yeh database ke andar ek pakki temporary/real table ki tarah data ko save (store) karke rakhta hai.

Kaise kaam karta hai: Isme data pehle se physical form mein disk par pada hota hai. Jab aap query chalate hain, toh database ko calculation karne ki zaroorat nahi padti, wo seedha save kiya hua data utha kar turant de deta hai (bohot fast!).

Refresh karna padta hai: Kyunki data pehle se save hai, isliye agar original table mein koi naya data aaye, toh Materialized View mein wo turant nahi dikhega. Aapko isey Refresh karna padta hai (manual ya automatic) taaki naya data update ho jaye.

Fayda: Speed lajawab hoti hai (Performance blazing fast), khaaskar heavy aur bade data warehouse ke liye.

Nuqsan: Disk space zyada ghertha hai (kyunki data duplicate save ho raha hai) aur data ko up-to-date rakhne ke liye refresh karna padta hai.

Feature	MySQL	PostgreSQL

Relational Database:

1. Custom Data Types

Normal types hote hain:

name TEXT
age INT

PostgreSQL mein tum apna khud ka data type bhi bana sakte ho.

CREATE TYPE address AS (
    city TEXT,
    country TEXT
);

Ab address ek custom type ban gaya.

CREATE TABLE users (
    name TEXT,
    home_address address
);

Use case: Jab same type ka structured data baar-baar use karna ho.

2. Complex Data Structures

PostgreSQL mein ek column ke andar structured data rakh sakte ho.

Example:

CREATE TABLE users (
    name TEXT,
    address JSONB
);

Data:

{
  "city": "Lahore",
  "country": "Pakistan",
  "zip": 54000
}

Yani address sirf ek simple string nahi, balki multiple related values ka structure hai.

Use case: User profile, product details, settings etc.

3. Arrays

Ek column mein multiple values store kar sakte ho.

CREATE TABLE students (
    name TEXT,
    skills TEXT[]
);

Data:

INSERT INTO students
VALUES ('Ali', ARRAY['Python', 'SQL', 'Java']);

Ab Ali ki skills mein 3 values hain.

Use case: Tags, skills, categories, multiple phone numbers etc.

4. JSON / JSONB

JSON ka matlab hai data ko JSON format mein store karna.

CREATE TABLE products (
    name TEXT,
    details JSONB
);

Data:

{
  "color": "black",
  "size": "large",
  "brand": "Nike"
}

JSONB PostgreSQL ka optimized binary JSON format hai, jo querying/indexing ke liye generally JSON se zyada useful hota hai.

Use case: Jab data ka structure har record mein thoda different ho sakta ho.

Example:

Product 1 → color, size, brand
Product 2 → color, weight, material
5. Functions

PostgreSQL mein database ke andar functions bana sakte ho.

Example:

CREATE FUNCTION add_numbers(a INT, b INT)
RETURNS INT
AS $$
BEGIN
    RETURN a + b;
END;
$$ LANGUAGE plpgsql;

Phir:

SELECT add_numbers(10, 20);

Result:

30

Yani database khud ek specific piece of logic execute kar sakta hai.

Use case: Repeated calculations, business logic, data processing.

6. Inheritance

PostgreSQL mein ek table dusre table ki properties inherit kar sakti hai.

Example:

CREATE TABLE person (
    name TEXT,
    age INT
);

Ab:

CREATE TABLE student (
    roll_no INT
) INHERITS (person);

student ke paas automatically:

name
age
roll_no

hain.

Yani student ne person ki columns inherit kar li.

Use case: Similar types ke records ko organize karna, although modern applications mein inheritance ka use relatively uncommon hai.

## 1. JSON / JSONB

**JSONB** generally querying/indexing ke liye zyada useful hota hai.

```sql
SELECT details->>'ram'
```

```text
16
```


Sab ke attributes different ho sakte hain, isliye JSONB useful hai.

# 4. Window Functions

### Concept

Window function rows ke **group ke context mein calculation** karti hai, lekin individual rows ko remove nahi karti.

Ye thoda important concept hai.

Example employees:

| name  | department | salary |
| ----- | ---------- | -----: |
| Ali   | IT         | 100000 |
| Ahmed | IT         |  80000 |
| Sara  | HR         |  70000 |
| Hina  | HR         |  60000 |

Agar har employee ki salary ke saath uske department ka ranking number chahiye:

```sql
SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS rank
FROM employees;
```

Result:

| name  | department | salary | rank |
| ----- | ---------- | -----: | ---: |
| Ali   | IT         | 100000 |    1 |
| Ahmed | IT         |  80000 |    2 |
| Sara  | HR         |  70000 |    1 |
| Hina  | HR         |  60000 |    2 |

### Important difference

`GROUP BY` rows ko combine kar deta hai.

Window function **rows ko retain** karti hai aur additional calculation deti hai.

Common window functions:

```text
ROW_NUMBER()
RANK()
DENSE_RANK()
SUM() OVER()
AVG() OVER()
```

# 5. CTE — Common Table Expression

### Concept

CTE ka matlab **Common Table Expression** hai.

Isko simple words mein:

**Complex query ke ek part ko temporary named result bana do.**

CTE `WITH` se start hoti hai.

### Example

Pehle employees ki high salaries find karte hain:

```sql
WITH high_salary AS (
    SELECT *
    FROM employees
    WHERE salary > 100000
)
SELECT *
FROM high_salary;
```

Yahan:

```text
WITH high_salary AS (...)
          ↓
Temporary result
          ↓
SELECT * FROM high_salary
```

### Real-life use

Complex query ko readable aur manageable banane ke liye.

Example:

```sql
WITH sales_total AS (
    SELECT customer_id, SUM(amount) AS total
    FROM orders
    GROUP BY customer_id
)
SELECT *
FROM sales_total
WHERE total > 100000;
```

# 6. Triggers

### Concept

Trigger ek aisa database mechanism hai jo **kisi event ke automatically hone par action perform karta hai**.

Events:

Hum automatically ek audit table mein record save karna chahte hain.

Example concept:

```sql
CREATE TRIGGER salary_update_trigger
```

# 7. Partitioning

### Concept

Partitioning mein ek **large table ko smaller pieces (partitions)** mein divide kiya jata hai.

User ko logically ek hi table nazar aa sakti hai, lekin internally data partitions mein organized hota hai.

### Example

Suppose sales table mein **10 crore records** hain.

Hum date ke basis par partition kar sakte hain:

```text
Sales
 │
 ├── 2024
 ├── 2025
 └── 2026
```

Example:

```sql
CREATE TABLE sales (
    id INT,
    sale_date DATE,
    amount NUMERIC
) PARTITION BY RANGE (sale_date);
```

Phir partitions:

```text
sales_2024
sales_2025
sales_2026
```

### Benefit

Agar query sirf 2026 ka data maangti hai:

```sql
SELECT *
FROM sales
WHERE sale_date >= '2026-01-01';
```

Database unnecessary old partitions ko avoid kar sakta hai.

### Real-life use

Large:

* Sales tables
* Logs
* Transactions
* Time-series data

# 8. Materialized View

### Concept

Normal **View** ek saved query hoti hai.

Materialized View query ka **result physically store** karti hai.

Example:

Suppose humein daily sales ka expensive calculation repeatedly karna hai.

```sql
CREATE MATERIALIZED VIEW daily_sales AS
SELECT
    sale_date,
    SUM(amount) AS total_sales
FROM sales
GROUP BY sale_date;
```

Ab:

```sql
SELECT *
FROM daily_sales;
```

### Difference

**View:**

```text
Query
 ↓
Every time result calculate
```

**Materialized View:**

```text
Query
 ↓
Result store
 ↓
Later quickly read
```

Lekin data refresh karna padta hai:

```sql
REFRESH MATERIALIZED VIEW daily_sales;
```

### Real-life use

* Dashboards
* Reports
* Large aggregations
* Analytics

# OSI 7-Layer Model — Complete Networking Notes

## OSI Model kya hai?

**OSI (Open Systems Interconnection)** ek conceptual model hai jo network communication ko **7 layers** mein divide karta hai.

Har layer ka apna specific kaam hota hai.

```text
7. Application
6. Presentation
5. Session
4. Transport
3. Network 
2. Data Link
1. Physical
```

Yaad rakhne ka order:

**A P S T N D P**

> All People Seem To Need Data Processing

---

# Layer 7 — Application Layer

### Definition

Application Layer woh layer hai jo **network services ko directly applications ke liye provide** karti hai.

Important protocols:

### 1. HTTP

**HTTP = HyperText Transfer Protocol**

Web browser aur web server ke darmiyan communication ke liye use hota hai.

Example:

```text
GET /users
POST /login
```

Example:

```text
Browser ── HTTP Request ──► Server
Browser ◄── HTTP Response ── Server
```

---

### 2. HTTPS

**HTTPS = HTTP + TLS encryption**

Secure web communication ke liye use hota hai.

Example:

```text
https://example.com
```

HTTP mein data normally plaintext hota hai, jabke HTTPS mein communication encrypted hoti hai.

---

### 3. DNS

**DNS = Domain Name System**

Domain name ko IP address mein resolve karta hai.

Example:

```text
google.com
     ↓
142.250.x.x
```

DNS ko internet ka **phonebook** samajh sakte ho.

---

### 4. FTP

**FTP = File Transfer Protocol**

Network par files transfer karne ke liye use hota hai.

Example:

```text
Client ── file ──► FTP Server
```

---

### 5. SMTP

**SMTP = Simple Mail Transfer Protocol**

Email **send** karne ke liye use hota hai.

Example:

```text
Mail Client ── SMTP ──► Mail Server
```

---

### 6. POP3

**POP3 = Post Office Protocol version 3**

Email server se emails receive/download karne ke liye use hota hai.

---

### 7. IMAP

**IMAP = Internet Message Access Protocol**

Email ko server par manage/access karne ke liye use hota hai.

POP3 aur IMAP ka simple difference:

```text
POP3  → emails download karne ka traditional approach
IMAP  → emails server ke saath synchronize/manage karta hai
```

---

### 8. SSH

**SSH = Secure Shell**

Remote computer/server ko securely access karne ke liye use hota hai.

Example:

```bash
ssh user@server
```

---

### 9. WebSocket

WebSocket **persistent, full-duplex communication** provide karta hai.

Example:

```text
Client ◄══════════► Server
```

Chat application:

```text
User A ── message ──► Server
User B ◄── message ── Server
```

---

# Layer 6 — Presentation Layer

### Definition

Presentation Layer ka kaam data ko **format, encode/decode, encrypt/decrypt aur compress/decompress** karna hota hai.

Common concepts:

### 1. Encryption

Data ko secure format mein convert karna.

Example:

```text
Hello
  ↓
Encrypted data
```

TLS/SSL ko traditionally Presentation Layer se associate kiya ja sakta hai, although modern networking mein TLS ko OSI ki ek single layer se strictly map karna perfect nahi hai.

---

### 2. Encoding

Data ko ek particular format mein represent karna.

Examples:

```text
UTF-8
ASCII
Base64
```

---

### 3. Serialization

Data ko transmission/storage ke format mein convert karna.

Examples:

```text
JSON
XML
```

Example:

```json
{
  "name": "Ali",
  "age": 20
}
```

# Layer 5 — Session Layer

### Definition

Session Layer **communication session establish, maintain aur terminate** karne ka concept handle karti hai.

Example:

```text
Client
  │
  │── Start Session
  │
  │── Communication
  │
  │── End Session
  ↓
Server
```

Examples/concepts:

* Session management
* Authentication sessions
* Dialog control
* Session establishment
* Session termination

Modern TCP/IP implementations mein Session Layer ka kaam aksar Application Layer aur libraries/protocols ke andar handle hota hai.

# Layer 4 — Transport Layer

Ye **bohat important layer** hai, especially Node.js/backend developers ke liye.

### Definition

Transport Layer **end-to-end communication** provide karti hai.

Main protocols:

## 1. TCP

**TCP = Transmission Control Protocol**

TCP reliable aur ordered data delivery provide karta hai.

Features:

* Connection-oriented
* Reliable
* Ordered delivery
* Error detection
* Flow control
* Congestion control

### TCP 3-Way Handshake

```text
Client                    Server
  │                         │
  │──── SYN ───────────────►│
  │                         │
  │◄─── SYN + ACK ─────────│
  │                         │
  │──── ACK ───────────────►│
  │                         │
  │    Connection Ready     │
```

Example:

```text
HTTP
  ↓
TCP
  ↓
IP
```

---

## 2. UDP

**UDP = User Datagram Protocol**

UDP connection establish kiye baghair datagrams send karta hai.

Features:

* Connectionless
* Faster/lower overhead
* No guaranteed delivery
* No guaranteed ordering
* No TCP-style retransmission

Example use cases:

* DNS
* Online gaming
* Live streaming
* Voice/video communication

Simple comparison:

```text
TCP → Reliability first
UDP → Speed/low overhead first
```

🔐 TLS kaam kaise karta hai?

Maan lo tum browser se https://example.com open karte ho.

1. Client → Server: "Hello"
Browser server ko batata hai ke woh TLS support karta hai aur kaunse encryption methods use kar sakta hai.

2. Server → Client: "Ye meri identity hai"
Server apna digital certificate bhejta hai. Certificate prove karta hai ke server waqai us domain ka authorized server hai.

3. Key exchange hota hai 🔑
Browser aur server securely ek shared secret/session key establish karte hain.

4. Secure connection start 🚀
Ab actual data — passwords, messages, cookies, etc. — encrypted form mein travel karta hai.

Example:

Password: 123456

Network par directly 123456 nahi dikhega. Uski jagah encrypted data jayega, jise bina proper session key ke samajhna practically infeasible hota hai.

TLS 3 cheezein provide karta hai
🔒 Confidentiality — data doosre log easily read nahi kar sakte.
🛡️ Integrity — data raste mein modify hua to detect ho sakta hai.
✅ Authentication — certificate ke through server ki identity verify hoti hai.

1. git reset — “Branch ko peeche le jao”

Maan lo history:

A → B → C → D   ← main

Aap chahte ho main ko B par wapas le jaana.

git reset --hard B

Ab:

A → B   ← main

C, D  ❌

Yani reset branch ka pointer peeche move karta hai.

Important: Shared/public branch par reset dangerous ho sakta hai, kyunki history rewrite hoti hai.

2. git revert — “Purane change ko undo karo”

Same history:

A → B → C → D   ← main

Agar C mein bug tha, lekin history delete nahi karni:

git revert C

Git ek new commit banayega:

A → B → C → D → C-undo   ← main

Yani C delete nahi hua. Uske changes ko reverse karne wala new commit create hua.

Revert shared branches ke liye generally safer hai.

Easy example

Suppose C commit mein tha:

Add payment feature

git revert C karein to Git ek new commit banayega:

Revert "Add payment feature"
3. git rebase — “Meri commits ko doosri jagah dobara laga do”

Ye thoda different hai.

Suppose:

A → B → C          main
     \
      D → E        feature

Main mein naye changes aa gaye aur aap apni feature branch ko latest main ke upar lana chahte ho.

git checkout feature

Result:

A → B → C          main
         \
          D' → E'  feature

Aapki D aur E commits new commit IDs ke saath latest main ke upar replay ho gayi.

Isliye rebase history ko clean/linear banane ke liye commonly use hota hai.









1. CSRF — Cross-Site Request Forgery 🎭

Ismein attacker user ke already logged-in session ka misuse karwane ki koshish karta hai.

Example:

Tum kisi website par login ho. Phir attacker tumhe ek malicious page/link par le jata hai jo tumhare browser se us website ko request bhejne ki koshish karta hai.

Tum logged in ho
      ↓
Attacker ka page
      ↓
Tumhare browser se request
      ↓
Target website

Django ka protection: CSRF token.

2. SQL Injection 💉

Ismein attacker input field mein malicious SQL inject karne ki koshish karta hai.

Suppose website ka login input hai:

Username: ______
Password: ______

Agar developer raw SQL ko unsafe tareeqe se construct kare, attacker input ke through query ka meaning change karne ki koshish kar sakta hai.

Result potentially:

Unauthorized access
Data read karna
Data modify/delete karna

Django ka protection: Django ORM normally parameterized queries use karta hai, jis se SQL injection ka risk kaafi reduce hota hai.

3. XSS — Cross-Site Scripting 🖥️

Ismein attacker website ke page mein malicious JavaScript inject karne ki koshish karta hai.

Example:

Comment:
"Nice post!"

Agar website user input ko properly escape na kare, attacker malicious script insert kar sakta hai.

Phir doosre users ka browser us script ko execute kar sakta hai.

Potential impact:

User ke session/data ko target karna
Fake content/UI dikhana
User ke browser mein unwanted actions karna

Django ka protection: Django templates mein variables ko by default HTML-escape karta hai.

4. Clickjacking 🖱️

Ismein attacker ek fake/invisible layer ke through user se click karwane ki koshish karta hai.

Example:

User ko nazar aa raha:
[ Play Video ]


Actually hidden layer:
[ Important Button ]

User sochta hai woh video par click kar raha hai, lekin click kisi doosre action par chala jata hai.

Django ka protection: X-Frame-Options middleware / related browser protections.
